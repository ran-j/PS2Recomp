# PS2Recomp Getting Started Guide (Windows)

This guide is for technically comfortable Windows users who are new to CMake,
native C++ projects, and PS2 recompilation.

> [!IMPORTANT]
> PS2Recomp is experimental. It does not convert an arbitrary PS2 ISO into a
> finished Windows game with one click. Analysis and recompilation are the
> beginning of a game-specific development and debugging process.

## 1. What the tools do

PS2Recomp works with the PS2 executable stored on a game disc:

- **ISO:** an image of the entire game disc.
- **ELF:** the game's executable program, comparable to a Windows `.exe`.
- **ps2xStudio:** graphical interface for analysis and recompilation tasks.
- **ps2xAnalyzer:** examines an ELF and produces a TOML configuration.
- **ps2xRecomp:** uses the ELF and TOML configuration to generate C++.
- **ps2xRuntime:** provides the environment needed by recompiled PS2 code.

Commercial PS2 executables often have names such as `SLUS_123.45`,
`SCUS_123.45`, `SLES_123.45`, or `SCES_123.45`. They usually do not have an
`.elf` extension, but they are ELF files internally.

## 2. Requirements

You need:

- 64-bit Windows
- Visual Studio with the **Desktop development with C++** workload
- CMake 3.20 or newer
- Git
- A tool capable of opening ISO files, such as 7-Zip
- A legally obtained ISO dumped from a disc you own

Visual Studio includes suitable copies of CMake and Ninja. You do not need to
build the downloaded CMake source package yourself.

This workspace has been built with:

- Visual Studio Community 2026
- The CMake and Ninja copies bundled with Visual Studio
- A 64-bit Debug configuration

## 4. Extract the executable from an ISO

Do not select the ISO itself in ps2xStudio. The file picker permits arbitrary
files, but the analyzer expects an ELF.

1. Open your `.iso` in 7-Zip.
2. Extract the ISO contents into a dedicated working folder.
3. Find `SYSTEM.CNF` in the extracted files.
4. Open `SYSTEM.CNF` in Notepad.
5. Find the line beginning with `BOOT2`.

For example:

```text
BOOT2 = cdrom0:\SLUS_123.45;1
```

In this example, `SLUS_123.45` is the main ELF. The `;1` is an ISO filesystem
version suffix and is normally not part of the extracted Windows filename.

Keep the complete set of extracted disc files. The ELF may later need data,
modules, audio, or other assets from the disc.

## 5. Run a quick analysis in ps2xStudio

The Studio analyzer is useful for confirming that the ELF can be parsed and
for quick experimentation.

1. Start `ps2xStudio.exe`.
2. Choose **File > Open** or use the file-selection control.
3. Select the main ELF identified through `SYSTEM.CNF`.
4. Click **Run Analysis**.
5. Watch the status and log panels for warnings or errors.
6. After analysis completes, save the generated configuration to a sensible
   game-specific working directory.

If the executable has no `.elf` extension, change the file dialog filter to
show all files.

This native analysis is a fallback for retail games. Commercial games commonly
have stripped symbols, which makes automatic function discovery less accurate.

## 6. Preferred workflow for a retail game

For serious work on a commercial game, use Ghidra:

1. Install Ghidra and create a project for the game.
2. Import the main ELF into Ghidra.
3. Allow Ghidra to analyze it.
4. Run the provided script:

   ```text
   ps2xRecomp\tools\ghidra\ExportPS2Functions.java
   ```

5. Keep both the TOML configuration and CSV function map generated by the
   script.
6. Confirm that the TOML `ghidra_output` field points to the CSV.
7. Pass the TOML to `ps2_recomp.exe`, or import the Ghidra output into Studio.

Ghidra generally identifies function boundaries in stripped retail games more
reliably than the quick native analyzer.

## 7. Rebuild the project

Use an **x64 Native Tools Command Prompt for Visual Studio**, then change to the
project directory.

To configure a Debug build using already downloaded dependencies:

```powershell
cmake -S . -B out/build/x64-Debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DFETCHCONTENT_FULLY_DISCONNECTED=ON
```

To build everything:

```powershell
cmake --build out/build/x64-Debug
```

To rebuild only Studio:

```powershell
cmake --build out/build/x64-Debug --target ps2xStudio
```

`FETCHCONTENT_FULLY_DISCONNECTED=ON` prevents CMake from contacting GitHub
during every configuration pass. Use it only after the dependencies have
already been downloaded.

## 8. Common problems

### `SDL2d.dll was not found`

Rebuild the `ps2xStudio` target. The project now copies `SDL2d.dll` for Debug
builds and `SDL2.dll` for Release builds beside the executable.

Do not rename `SDL2.dll` to `SDL2d.dll`; Debug and Release libraries may not be
interchangeable.

### Studio opens but analysis fails immediately

Check that you selected the boot ELF named in `SYSTEM.CNF`, not:

- the ISO itself;
- `SYSTEM.CNF`;
- an IOP module;
- an arbitrary data file.

### The file does not appear in Studio's dialog

Select the all-files filter. PS2 retail ELFs often have no `.elf` extension.

### CMake tries to access GitHub and fails

If all dependencies are already present, configure with:

```powershell
-DFETCHCONTENT_FULLY_DISCONNECTED=ON
```

If dependencies are missing, Git/network access must work for the initial
configuration.

### Analysis succeeds, but the generated program does not run

That is expected for many games. PS2Recomp currently has incomplete graphics,
VU1, and hardware support. A working port may require:

- correcting function boundaries;
- implementing missing syscalls and runtime stubs;
- handling game-specific I/O;
- adding game overrides;
- debugging generated C++;
- repeated cold-boot testing.

## 9. Recommended working layout

Keep project files, extracted disc contents, and generated output separate:

```text
PS2Recomp\
  out\build\x64-Debug\       # Build products

PS2Games\
  MyGame\
    disc\                    # Extracted ISO contents
    analysis\                # Ghidra project, CSV, and TOML
    generated\               # Generated C++ output
```

Avoid editing generated build files under `out\build` manually. Change the
source or CMake files and rebuild instead.

## 10. A realistic first milestone

A good first goal is:

1. Extract the correct ELF.
2. Confirm Studio can load and analyze it.
3. Import it into Ghidra.
4. Export a function map and TOML.
5. Generate C++ successfully.
6. Record the first runtime error and address one blocker at a time.

Reaching generated C++ does not mean the game is playable, but it confirms that
the extraction, analysis, and recompilation toolchain is working.
